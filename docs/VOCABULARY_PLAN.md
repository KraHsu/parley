# 词句学习功能开发计划

状态：待实施。基线为 Parley v0.1.0（`f2df911`）。本计划细化总计划的 M3 词句收藏与 M4 轻量复习，功能尚未实现。

## 1. 目标与交付顺序

完成学习闭环：**遇到词句 → 查看解释 → 保存原句与自己的理解 → 离线检索 → 主动回忆 → 回到对话使用**。

按两个可独立发布的版本推进：

| 版本 | 交付范围                                                                      | 完成后的用户能力                                 |
| ---- | ----------------------------------------------------------------------------- | ------------------------------------------------ |
| v0.2 | 收藏、来源快照、释义与注释、列表与筛选、编辑与回收站、JSON 导入导出、CSV 导出 | 从真实对话积累自己的词句本，离线使用且可迁移数据 |
| v0.3 | 标签、复习卡片、到期队列、复习记录、可选表达练习                              | 持续回忆和使用收藏的表达                         |

词、短语、完整句子采用同一套收藏流程。首版允许没有释义的收藏，先保留材料；进入复习前提示补充答案。

延后：云同步、共享词库、音频/发音评分、OCR、外部词典抓取、自动提取整段对话中的生词、自动生成课程、复杂自适应复习算法、Anki 专用格式。任意语言都可以手动选择文本和录入，不以自动分词作为前置条件。

## 3. 用户流程

### 3.1 从对话收藏，不需要复制

- 桌面工作台：在主聊或辅导消息内选中词句，出现“解释 / 翻译 / 收藏”操作；每条消息另提供可通过键盘访问的“收藏整句”。
- 终端伴随：在 GUI 自动同步的内容中选中词句收藏。补充最近消息切换，允许收藏自己的表达及稍早的回复；首版范围为当前已同步的最近 6 个 turn，完整历史浏览另行迭代。
- 官方终端本身的鼠标选区由终端管理，本计划从 GUI 中同步的消息捕获选区。用户不需要往返剪贴板，也不需要改变 Codex 的快捷键。
- 点击收藏打开编辑抽屉：词句、语言、原句已填入；可添加释义和个人注释，点击“保存”。已收藏的来源显示“查看收藏”，避免连点生成重复记录。
- 提供“手动添加”，允许离线录入；没有来源时仍能正常收藏。

例：在 `How have you been?` 中选中 `have you been`，保存词句、完整原句和“询问最近过得怎么样”的解释。以后即使终端会话不再可读，仍可看到这份材料。

### 3.2 收藏与 AI 答疑

- 收藏、编辑、搜索、导出和普通复习均不要求连接 Codex。
- “请助手解释”是明确的用户动作，复用当前辅导通道和选定模型，不增加后台模型轮询。
- 请求附带收藏词句、原句、语言和问题；打开抽屉、保存收藏、进入复习均不触发模型请求。
- 用户可以在辅导答案中选段，直接“用作当前词句释义”或“添加到注释”，无需复制，也不自动将整篇回答写入词典。
- 请求开始时固定目标词条 ID 和编辑版本；切换词条、删除词条或后续编辑后，迟到回复仍作为可选答案展示，不覆盖已保存内容。
- 额度不足、离线、模型错误不阻塞本地保存。首版不要求模型输出结构化词典 JSON，不硬编码 Luna 可用性。

### 3.3 词句本与编辑

- 列表展示词句、语言、简短释义和更新时间；详情展示全部释义、注释及多条来源原句。
- 搜索覆盖词句、释义、注释；按语言、词/短语/句子、是否有释义筛选，支持最近收藏/最近更新排序。v0.3 增加标签和复习状态。
- 一条词条表示一个需要学习的意思。同一拼写可保留不同意思；再次遇到时，用户可以“补充到已有词条”或“新建另一条”。不按拼写强制合并。
- 编辑使用明确“保存”按钮。未提交内容作为本地编辑草稿保存，切换页或重启后可继续；草稿不计入正式收藏数量。
- 删除先进入回收站，提供立即撤销及稍后恢复。彻底删除需确认，才移除所属来源和复习数据；删除聊天只解除来源链接，保留收藏快照。
- 语法窗口内以“答疑 / 词句 / 复习”切换或抽屉呈现，保留辅导草稿。窗口最窄 420px 时，列表与详情分步展示。

## 4. 选择区间与多语言约定

1. 仅接受一条消息正文中的连续选区；跨消息选择先提示重新选择，避免把两个来源错误拼在一起。
2. 点击操作时固定正文、来源、选区和语言。流式回复、2 秒轮询或切换会话不得替换已打开收藏抽屉的材料。正在选择时暂停会改变该区域内容或位置的更新，结束后再显示新内容。
3. 保存原始选中文本和原句快照，定位采用相对快照的 Unicode 标量值区间 `[start, end)`。Vue 将 DOM UTF-16 偏移显式转换，Rust 校验区间和选中文本吻合；不使用首次字符串匹配定位重复词。
4. 保存快照哈希与定位格式版本。正文变化、来源删除或找不到精确位置时显示快照，不将旧区间套到新正文上。终端截断文本明确标注，不声称保存了完整消息。
5. 原始拼写不改写；查询另建 NFC 规范化键。第一版匹配保留大小写及重音区别，不用 SQLite 默认大小写比较假定支持所有语言。更宽松匹配可后续增加独立查询键，不参与词条唯一性判断。
6. 输入和展示兼容中文、日语、组合重音、emoji、RTL 和中外文混排。选择边界不得切开代理对或可见组合字符，错误区间拒绝保存并保留草稿。
7. 新词条默认使用来源会话的目标语言；终端来源没有 Parley 语言信息时用当前目标语言，用户可修改。切换全局语言不改写已有词条。补充 BCP 47 语言代码/名称输入，移除只能选择 8 种预设的限制。

首版输入上限：词句 2,000 个 Unicode 标量值、释义 8,000、注释 16,000、单条来源快照 16,000；超限明确提示并允许用户缩小选区，不静默截掉用户输入。终端读取已有截断上限继续保留并显式展示。

## 5. 数据结构与迁移

使用 `002_vocabulary.sql` 增量创建词句数据，保持现有会话表和 ID 不变；v0.3 用 `003_vocabulary_review.sql` 增加标签及复习。迁移按版本顺序在事务中执行，覆盖从空库与 v0.1.0 升级两条路径。

| 表                                          | 主要字段                                                                                                                                                                  | 约束与行为                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `vocabulary_entries`                        | id、language、language_label、kind、text、lookup_key、meaning、meaning_language、note、revision、created_at、updated_at、deleted_at                                       | UUID 标识词条；同词同语言允许多义，不加拼写唯一约束；修改递增 revision         |
| `vocabulary_occurrences`                    | id、entry_id、source_kind、conversation_id、message_id、thread_id、turn_id、item_id、role、selected_text、snapshot、snapshot_hash、start、end、locator_version、truncated | 一条词条多个语境；来源分 main/tutor/terminal/manual/import；快照不依赖聊天存活 |
| `vocabulary_drafts`                         | id、entry_id 可空、payload、base_revision、updated_at                                                                                                                     | 自动保存未提交表单；正式保存后同一事务清除草稿                                 |
| `vocabulary_mutations`                      | request_id、operation、result_id、created_at                                                                                                                              | 创建、关联来源、导入和评分的重试幂等凭据，避免“成功但响应丢失”后重复写入       |
| `vocabulary_tags` / `vocabulary_entry_tags` | tag_id、name / entry_id、tag_id                                                                                                                                           | v0.3 加入，多对多，按标签 ID 关联                                              |
| `vocabulary_cards`                          | id、entry_id、direction、stage、due_at、last_reviewed_at、suspended、schedule_version、revision                                                                           | v0.3 加入，每词条每方向至多一张卡                                              |
| `vocabulary_reviews`                        | id、card_id、request_id、rating、reviewed_at、before_state、after_state                                                                                                   | v0.3 加入，评分和更新排程同一事务提交，可撤销最近一次评分                      |

关键一致性约定：

- 复用 `Storage` 的连接、事务和进程锁；新模块不另行打开写连接。列表分页读取，建议每页 50 条，不随聊天启动一次性加载全部词句。
- 本地消息的唯一键是 **`(conversation_id, id)`**，不是单独 message ID。关联来源需要同时携带会话 ID；本地链接可通过复合外键 `ON DELETE SET NULL` 保留快照，外部 Codex ID 只作来源元数据。
- 基于来源、快照、区间识别重复收藏并提示已存在；写请求 ID 解决重试幂等，两者分别处理。用户主动保存另一种意思时允许新词条。
- `revision` 防止抽屉、异步答案和导入结果覆盖较新的编辑。冲突保留本地草稿，允许重新加载比较。
- 正式保存成功提示必须晚于事务提交。写失败保留表单，重试沿用 request ID；关闭窗口时统一等待词句草稿和在途写入，沿用当前超时、重试和显式放弃流程。
- 迁移失败回滚；新版数据库继续拒绝被旧版应用写入。升级前备份方法与现有工作区备份说明一致，不声称能自动降级到 v0.1.0。

## 7. 导入导出

- JSON 为完整词句备份，包含格式版本、稳定的导出数据集标识、词条、来源快照，以及 v0.3 的标签、卡片和复习记录。默认仅导出正式有效词条；回收站可显式包含，编辑草稿单独标明不在导出范围。
- JSON 不包含 ChatGPT 账号邮箱、凭据、CLI 路径或完整聊天历史。来源定位仅用于材料追溯；导入其他工作区后默认视为快照，不凭同名 ID 自动连接本地聊天。
- 导入先预览格式版本、词条数量、新增/重复/冲突情况，再提交。相同数据集与记录重复导入幂等；同 ID 不同内容默认保留本地，允许显式作为另一条导入，不静默覆盖个人修改。
- 首版导入上限 20 MiB、10,000 词条，并检查来源条数、总文本大小和字段上限；验证全部通过后一次事务提交。格式错误、引用缺失、过大或未知新版格式不进行部分写入。
- 导出写入临时文件后原子替换目标文件；取消选择或写入失败不显示成功，不破坏已有导出。
- CSV 为通用阅读/表格交换格式，每行一个词条，包含语言、原文、释义、注释和一条主要原句；不承担完整恢复。处理引号、换行、UTF-8 和公式起始字符，说明导出转义行为。CSV 导入延后。

## 8. v0.3 轻量复习设计

默认是“目标语言词句 → 回忆含义”；有释义的词条才可加入队列。可手动启用“母语提示 → 回忆目标表达”，两个方向独立排程；不自动为所有词条创建两张卡。

用户流程：开始复习 → 先看问题 → 在心里或输入框回忆 → 显示答案/原句 → 自评“忘记 / 吃力 / 记住” → 下一张。以自评为准，拼写差异和同义表达不自动判错。

首版采用可解释、可测试的固定阶梯，作为产品默认值，不声明经过个体学习效果验证：

| 自评 | 下一次安排                        | 阶段变化                                  |
| ---- | --------------------------------- | ----------------------------------------- |
| 忘记 | 10 分钟后到期                     | 回到初始阶段                              |
| 吃力 | 1 天后到期                        | 保留当前阶段                              |
| 记住 | 按 1 / 3 / 7 / 14 / 30 天阶梯安排 | 初次为 1 天，之后逐级增加，最高保持 30 天 |

- Rust 注入时钟执行确定性排程；保存 UTC 时间戳，天按 24 小时计算，本地时间仅用于显示。切换时区、跨午夜和夏令时不能重复评分。
- 队列优先到期卡，再补充新卡；默认一次最多 20 张、新卡最多 5 张，可调整。10 分钟重学尚未到期时显示下一次时间，不强制用户留在页面等待。
- 中途退出保留已经提交的评分；未评分卡不推进。仅允许撤销最近一次且未被后续更新覆盖的评分，恢复评分前状态。
- 卡片暂停、词条进入回收站、彻底删除或编辑答案都有明确行为：暂停/回收站不出题；内容编辑保留排程并提供重置选项；彻底删除移除所属卡片与复习记录。
- 仅展示本地可计算的数量：收藏数、到期数、今日完成数；不根据收藏数量推断词汇量或学习水平。
- “用这个表达练一句”是可选辅导动作，用户点击后才发送模型请求；完成后仍由用户判断掌握程度，不影响官方终端的正常对话。

## 9. 实施阶段与验收

| P1 数据基础             | 1.5–2 天 | migration 002、CRUD、来源和草稿事务；旧库升级、回滚、重试幂等、删除聊天保留快照通过 Rust 测试                      |

每阶段保持可运行，建议提交分别围绕数据存储、选区收藏、词句管理、数据交换、复习排程、复习界面；不把所有功能积累成一次大型提交。

性能目标以开发基准机器记录：10,000 条词条时，首页只加载一页；本地搜索请求到结果完成的 P95 目标小于 300ms（不含输入防抖）。先用索引和参数化查询测量；不达标再决定是否增加全文索引，并单独验证 CJK 搜索，不提前引入词典服务或搜索引擎。

每阶段运行与变更相关的 Rust / Vitest 测试，交付前执行 `npm run check`、`npm test`、`cargo test --workspace --locked`、`npm run package:linux`。真实模型测试仅用于验证用户触发的答疑流程；日常 CI 不使用账号或模型额度。Windows/macOS 编译结果与真机验证分别记录。

v0.2 完成定义：用户可从工作台或终端伴随 GUI 无复制地收藏词句，保存原句与注释；重启且不连接 Codex 仍能搜索和编辑；删掉聊天后材料仍在；JSON 导出到新工作区可恢复正式词句数据；升级不丢现有会话；安装包和文档明确平台范围。
