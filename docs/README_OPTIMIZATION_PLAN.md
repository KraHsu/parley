# README 改版计划

状态：首版已实现，按最新要求取消所有演示托管与演示入口。关联：[宣传计划](PROMOTION_PLAN.md) · [视频脚本](marketing/VIDEO_SCRIPTS.zh-CN.md)。

## 1. 目标与范围

让第一次打开仓库的人，在约 10 秒内理解 Parley 的用途，并找到真实可用的入口。主页以产品价值和使用方式为主，技术细节通过专门文档展开。

**主标语：边聊，边懂，边记住。**

解释：用目标语言对话，随时理解词句，把想学的表达留给下一次复习。

首轮以中文 README 为主。英文 README 根据后续反馈再补，不提前放置空的语言切换入口。

## 3. 视觉方向

沿用 `parley.` 字标与紫色强调色。正文用 GitHub 原生 Markdown 排版，标题和说明保持真实文字，视觉素材仅承担品牌识别。

- 浅色背景、大留白、清晰层级；暗色主题使用对应的横幅。
- 最多三个徽章：License、CI、Web，避免堆积厂商和技术栈 logo。
- 主要素材为 `docs/media/readme-hero-light.svg` 与 `readme-hero-dark.svg`，1600 × 520，每张预算小于 120 KB。
- 四个能力与三种使用方式用文字和表格表达；不放演示截图、视频封面、播放按钮或演示链接。
- 视频及其制作素材另存于本机，由维护者自行发布到 YouTube 等平台。它们不进入 Git，不由 Web 或 GitHub Release 托管。

## 4. README 阅读顺序

1. **首屏**：品牌、标语、一句解释、Web 主入口、桌面安装说明；就近注明 Web 使用自己的 API。
2. **四个具体能力**：目标语言交流、解释 / 翻译 / 怎么说、带原句的词句收藏、后续复习。
3. **使用方式**：Web、桌面工作台、原生终端伴随的简短对照。
4. **开始使用**：Web 三步；终端保留 `parley-cli`，高级参数跳转指南。
5. **当前状态与常见问题**：预览版、API 与 CLI 区别、本地数据、CORS、平台验收；详情折叠或链接。
6. **参与开发**：技术栈、最短开发命令、文档导航和贡献入口。
7. **许可**：MIT 与独立项目说明。

## 5. 执行与验收

| 阶段       | 工作                                    | 完成条件                             |
| ---------- | --------------------------------------- | ------------------------------------ |
| 内容校准   | 对照 Web、后端、安装与数据文档重写正文  | 产品描述、凭据要求和当前验收状态一致 |
| 视觉改版   | 制作浅色 / 深色品牌横幅，调整标题和表格 | 不依赖演示媒体，也能清楚理解用途     |
| 仓库发布   | 更新 README、About、Homepage、Topics    | 入口可用，文档链接和图片路径有效     |
| 发布后调整 | 收集首屏理解与开始使用问题              | 将重复问题转为文档修正或明确 issue   |

检查项：

- GitHub 桌面和手机、深色和浅色主题均检查。
- 首屏静态素材预算不超过 1 MB；本次演示截图、播放器、字幕和录制工具不出现在提交或 Web 构建中。
- 核心能力可在当前应用中找到，不暗示语音对练、发音评分、自动同步或已经完成所有厂商实测。
- 相对链接和实际入口有效，`npm run format:check` 与 `npm run web:build` 通过。
- 后续邀请 5 位未参与开发的人看前两屏，目标为至少 4 人能说明用途、入口和凭据要求；这是待执行的用户反馈目标，不是已有调查结果。

预计内容与视觉工作约 1–2 天；发布后的反馈调整按问题数量安排。暂停真实 API 厂商实测的要求保持有效。
