# 0.4.0-alpha.2 修复记录

本次修复依据项目检查中的数据读写、会话连续性、性能和发布问题。

| 问题                        | 修改                                                | 验证                                           |
| --------------------------- | --------------------------------------------------- | ---------------------------------------------- |
| 单个过长标签使 Web 无法打开 | 写入与加载共用校验；错误页提供原始导出及标签修复    | 校验、IndexedDB 和真实浏览器旧数据恢复         |
| 恢复失败仍提示成功          | 先完成事务，再替换内存和清除密钥；失败保留导入预览  | 保存失败注入、事务回滚及浏览器刷新             |
| 大备份只能导出不能导入      | 新 `.jsonl` 逐行导入导出，继续读取旧 JSON           | 超过 32 MiB 的两种格式往返及截断拒绝           |
| 切换辅导任务重置会话        | 任务从模型/语言的会话边界中分离；Codex 每轮声明任务 | Pinia、Rust SQLite、Codex 输入与浏览器连续提问 |
| 输入随词库增长变慢          | 按记录标记和保存；词句列表每页 50 条                | 写入测试证明草稿不访问词库；浏览器分页及搜索   |
| 组件自行修改词句状态        | 词句操作集中到 learning 模块，两端共用标签校验      | 去重、字段上限、Unicode 及保存失败测试         |
| API 报错难以排查            | 两端共用错误分类，限量读取响应，筛选请求 ID         | 本地错误响应；不显示服务商正文或密钥           |
| 发布入口仍提供旧包          | 新版本使用独立包名和路径；旧 Release 标明停用       | Ubuntu 全新安装、旧包迁移、KDE 共存            |
| 验证分支可部署正式网站      | 工作流和 GitHub 环境均只允许 main                   | 工作流检查及远端环境策略查询                   |
| 缺少用户流程回归            | 加入 Playwright 和隔离本地 HTTP/SSE 服务            | PR Pages 工作流运行 test:web                   |
| 架构入口停留在旧方案        | 更新当前结构和真实发送流程，保留历史设计            | 与实际模块、存储和发布入口逐项核对             |

验证命令：`npm test`、`cargo test --workspace --locked`、`npm run check`、`npm run test:web`、`npm run package:linux`；安装验证使用 `scripts/test-deb-install.sh`，只在一次性容器内操作 APT。

草稿合成基准在本机使用相同的 5000 条词库和 20 次赋值，修复前约 884ms，修复后不足 1ms；此数字不含 DOM 和实际 IndexedDB 写入，不代表其他设备的帧率。自动测试额外检查草稿写入不访问词条或重写消息正文，以验证性能改动的原因。

没有测试真实厂商 API，没有修改用户当前安装和学习数据库；演示、视频和本地验证产物不进入 Git 或 Web 构建。浏览器的合成输入法事件回归不替代原生输入法或 Windows/macOS 真机验收。
