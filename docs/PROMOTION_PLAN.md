# Parley 宣传计划

状态：文字策划与脚本已完成。视频由维护者自行发布到 YouTube 等平台，不进入 Git、不在 Web 展示、不上传到 GitHub Release。本轮不新增真实 API 厂商实测。

配套：[README 改版](README_OPTIMIZATION_PLAN.md) · [分镜与完整口播](marketing/VIDEO_SCRIPTS.zh-CN.md) · [发布文案](marketing/PUBLISH_COPY.zh-CN.md)。

## 1. 主线与受众

**一段对话，留下一个想学的表达。**

用同一个英文生活场景贯穿对话、理解、收藏和复习。先让观众看到自己会怎样使用，再解释模型连接和技术栈。

| 受众                   | 开场切入点                       | 展示重点                       | 收尾行动               |
| ---------------------- | -------------------------------- | ------------------------------ | ---------------------- |
| 已接触 AI 的语言学习者 | 大概看懂一个表达，却不知道怎么用 | 主聊、解释、收藏、复习         | 打开 Web，留下一个表达 |
| 使用原生 CLI 的开发者  | 在终端旁随时理解外语             | Codex / Claude Code 与独立助手 | 阅读终端使用说明       |
| 愿意参与开源的使用者   | 想分享自己的学习方法或改进体验   | 具体能力与当前限制             | 提交一个可复现的问题   |

首轮中文讲解、英文示例。目标是发现阻碍开始使用的问题，不承诺播放量、用户增长或学习效果。

## 2. 内容组合

| 内容          | 规格              | 核心信息                         | 使用位置                        |
| ------------- | ----------------- | -------------------------------- | ------------------------------- |
| A：主介绍片   | 90 秒，横版       | 完整走一次“聊 → 懂 → 记 → 复习”  | YouTube 等维护者选择的视频平台  |
| B：发现型短片 | 30 秒，竖版       | 一个表达从对话进入词句本         | YouTube Shorts 或其他短视频渠道 |
| C：终端伴随片 | 60 秒，横版       | 原生 CLI 与 GUI 助手分别负责什么 | 技术向视频或开发者社区          |
| D：图文介绍   | 4 张图，约 300 字 | 痛点、解释、收藏、开始入口       | 维护者选择的图文渠道            |

统一示例：聊做饭时遇到 `getting the hang of`，理解“逐渐掌握……的窍门”，带原句收藏，再回到复习。逐镜安排与口播见[脚本文档](marketing/VIDEO_SCRIPTS.zh-CN.md)。

Git 只保留文字计划、脚本和发布文案。视频、字幕、音频、封面、截图、录屏与制作工具都在仓库外或忽略的本地目录保存。Web 仅提供应用，不增加演示播放器或展示页面；README 不安排演示入口。

## 3. 发布节奏

以维护者确认素材和渠道的日期为 T0，不预设实际发布日期。各平台的投稿要求在真正发布前核对。

| 时间 | 动作                                | 检查重点                                   |
| ---- | ----------------------------------- | ------------------------------------------ |
| T−2  | 校准 README、文案与例句             | Web 入口与凭据说明清楚，桌面不指向旧冲突包 |
| T−1  | 录制 / 剪辑 A、B，并邀请 3–5 人试看 | 能否理解双面板与收藏过程                   |
| T0   | 在 YouTube 等选定平台发布 A         | 标题、简介、实际画面与仓库说明一致         |
| T+1  | 发布 B 或 D                         | 记录最先出现的两个问题                     |
| T+3  | 发布 C 或终端静态讲解版本           | 观众能区分原生 CLI 与助手模型连接          |
| T+5  | 回答一个高频问题                    | 先修说明，再引导访问                       |
| T+7  | 复盘并修改 README 或开始使用说明    | 决定下一轮优先改入口、文案还是产品体验     |

GitHub 承接源码和使用说明，维护者负责视频平台发布。新 Linux 修复包公开前，桌面入口统一写“安装说明”，不宣传“下载最新版”。

## 4. 标题与开场

**主片标题：我做了个开源工具，把 AI 聊天变成语言练习**

开场口播：

> 用 AI 练英语，聊着聊着遇到一个表达：大概懂，却不知道自己该怎么用。
>
> 我做了一个开源工具，叫 Parley。左边继续聊天，右边专门解决这些卡住的地方。

**短片标题：这句英语，聊完以后怎么留下来？**

开场：

> 用 AI 练英语，遇到不会的表达，你会怎么处理？

**终端片标题：在 Codex 旁边，放一个语言助手**

开场：

> 如果你已经在用 Codex，又想顺便练语言，可以在终端旁边放一个语言助手。

完整分镜、连续口播、结尾行动分别在[视频脚本](marketing/VIDEO_SCRIPTS.zh-CN.md)；可直接复制的简介、置顶评论和图文说明在[发布文案](marketing/PUBLISH_COPY.zh-CN.md)。

## 5. 拍摄与表达规范

- 横版建议 1920 × 1080、30 fps；竖版 1080 × 1920，按操作重新取景，不缩成看不清的完整桌面。
- 每次选词、弹窗和页面切换后留观察时间；字幕不挡住按钮、例句和释义。
- 使用示例响应时，就近标明“界面演示 · 示例数据”；经过剪辑的片段不代表模型请求速度。
- 不展示真实密钥、个人路径或私人会话；没有连续终端素材时用清楚标注的静态讲解。
- 收藏是用户明确操作；复习展示“先回忆，再看答案”，不假装已经过去多天或已经掌握词句。
- 若使用合成口播，说明其来源并完整试听；每支保留无字幕版、字幕文件和独立音轨，供平台发布或重新配音。

## 6. 产品信息口径

| 主题        | 准确表达                                                                 |
| ----------- | ------------------------------------------------------------------------ |
| 开源        | 软件免费开源，模型服务使用各自的凭据与额度                               |
| Web         | API 直连；服务需允许浏览器 CORS；学习资料保存在当前浏览器                |
| 桌面        | 本地保存学习记录；原生终端与 GUI 助手分别配置                            |
| CLI         | 保留原生交互，同步范围以终端指南为准；不暗示每个 token 都实时同步        |
| Claude Code | 原生终端入口与需要独立 API Key 的 GUI 后端是不同方式                     |
| 功能        | 文字对话、表达提示、解释、翻译、收藏和复习；不宣传未实现的语音或跨端同步 |
| 验收        | 提供协议与预设不等于所有厂商均已真实验证                                 |

## 7. 反馈与复盘

不增加应用内追踪作为本轮前提。记录视频观看情况、是否找到入口、是否实际完成一次收藏、开始使用时最常卡在哪一步。

首轮邀请 5 位试看者，目标为至少 4 人能说明用途与凭据要求、至少 3 人能独立完成一次手动或示例词句收藏。播放量不能代替这些观察。记录使用[反馈模板](marketing/FEEDBACK.md)，尚未收到的反馈不填成已完成。

用途不清就修改前 5 秒和 README 首段；API 概念不清就补开始使用说明；连接问题集中出现时先收集错误和修复说明，再扩大传播。
