# UI 布局与交互

当前界面使用中性白、浅灰导航和紫色强调色。桌面端采用导航 / 工作区 / 语言助手三栏，运行环境与连接说明收进设置，主工作区只保留学习相关操作。

## 滚动约束

- `html`、`body`、`#app` 都固定尺寸并禁止滚动，`.app-shell` 使用 `100dvh`（`100vh` 回退）。
- 从外壳到各个内容面板的 grid/flex 子元素均设置 `min-width: 0`、`min-height: 0`，防止内容撑开窗口。
- 工具栏、辅导模式和输入框区域不可收缩，始终留在面板内。
- `.conversation-scroll`、`.tutor-scroll`、`.vocabulary-scroll` 和 `.history-scroll` 分别持有滚动。`overscroll-behavior: contain` 防止滚动传递到相邻区域。
- 文本输入框固定高度，长草稿在输入框内滚动，不能手动拖大整个布局。
- 设置使用原生 modal dialog；只有设置正文滚动，标题与底部按钮固定。
- 未来渲染实际消息和列表时，将其放入现有 scroll-region 内，不在外层增设可滚动页面容器。

## 响应式行为

| 宽度         | 布局                                         |
| ------------ | -------------------------------------------- |
| 1150px 以上  | 完整导航、主工作区、语言助手                 |
| 761–1150px   | 导航收为图标栏，主工作区与助手并排           |
| 601–760px    | 图标栏保留，用页签选择对话 / 助手 / 词句     |
| 600px 及以下 | 隐藏侧导航，由页签和顶部设置入口提供完整导航 |

Tauri 最小窗口为 780×640，仍保持主对话和辅导区同时可见。更窄模式也用于浏览器预览和放大显示时的布局降级。

## 当前可用交互

- 导航切换主对话和词句视图，`v-show` 保留两个面板的草稿/搜索状态。
- 话题卡按所选目标语言写入草稿并聚焦输入框，不自动发送。
- 语言助手切换“怎么说 / 解释 / 翻译”，更新提示及建议问题；点击问题填入辅导草稿。
- 词句搜索显示与输入对应的空状态，不制造假收藏数据。
- 母语与目标语言可在设置修改，主窗口也有目标语言快捷入口。
- 设置可通过 Escape、关闭按钮、完成按钮或点击遮罩关闭；原生 dialog 负责焦点约束。
- 模型发送已接入独立流式消息与停止操作；词句收藏仍未接入。草稿、消息与设置写入本地 SQLite，历史列表支持切换和删除。

## 本次验证

Chrome 实际验证 1920×1080、1440×900、1320×940、1150×720、1024×768、900×600、780×640、780×480、640×480、390×844、360×640；检查根元素尺寸、页面滚动位置及固定控件的边界。

在各消息/列表滚动区注入超过 2400px 的中英日韩/阿拉伯语长内容及长单词，使用真实鼠标滚轮事件确认滚动只发生在目标区域，工具栏和输入框位置保持不变。另验证语言切换、RTL 草稿、话题填入、辅导模式、视图切换保留草稿、搜索、设置与 Escape。

Linux Tauri/WebKit 实际启动后验证设置中的 Rust 调用，并在 780×640 下通过鼠标滚轮验证消息区滚动、顶部及两个输入框固定。本节描述 UI 阶段检查；后续已完成真实模型调用，见 [接入验证记录](VALIDATION.md#codex-接入首版)。
