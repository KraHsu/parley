# Parley 开发计划

状态：M0 已完成，M1/M2 的连接与双会话、M3 的工作区持久化已实现首版；官方 Codex TUI + 独立语法 GUI 及自动上下文已发布为 v0.1.0 Linux 预览版。词句收藏、注释与离线复习已实现，详细范围和验收以 [词句学习开发计划](VOCABULARY_PLAN.md) 为准。下方保留全产品里程碑，未完成项继续按验收推进；当前数据与接入能力见 [持久化说明](PERSISTENCE.md) 和 [Codex 接入说明](CODEX_INTEGRATION.md)。

## 1. 产品目标与边界

让用户在处理自己真正关心的话题时练习目标语言；遇到表达或理解障碍时，能通过母语辅导快速回到主对话。

首版交付闭环：

1. 用户在本机启动应用，设置母语、目标语言和学习水平。
2. 通过官方 Codex 登录流程登录自己的账号。
3. 在主窗口使用目标语言进行多轮对话。
4. 选中不懂的词句，在辅导区查看解释、母语翻译或语法分析。
5. 在辅导区输入母语意图，获得目标语言表达，手动插入主输入框。
6. 将词句、原句和注释保存到本地生词本。
7. 重启应用后继续会话，检索、修改或导出自己的学习数据。

首版优先桌面；Linux 是当前开发验证平台，同时配置 Windows/macOS 编译检查。辅导区先使用同一系统窗口内的侧栏，独立悬浮窗口在 M4 评估。

暂不纳入：移动端、云同步、多人协作、共享订阅、账号池、网页自动抓取、语音评分、自动课程生成、社交功能、应用内付费和自动更新。商业化不是当前目标。

## 2. 已确定的技术决策

| 领域      | 选择                                                | 原因和约束                                                 |
| --------- | --------------------------------------------------- | ---------------------------------------------------------- |
| 桌面      | Tauri 2 + Rust                                      | 管理本地进程、文件和数据库，Vue 不直接控制 shell           |
| 界面      | Vue 3 Composition API + TypeScript                  | 单文件组件，严格类型检查                                   |
| 构建      | Vite + npm                                          | 单一桌面应用采用平铺结构，减少工具链负担                   |
| 前端状态  | Pinia                                               | 分离设置、主会话、辅导会话、词句状态                       |
| 模型接入  | 官方 `codex app-server`，优先 stdio                 | 用户自己的账号与额度；协议与模型列表动态协商               |
| 本地存储  | SQLite，Rust 侧 `rusqlite`，在 M3 引入              | 事务、迁移、离线读取、备份和导出                           |
| 富文本    | 安全 Markdown 渲染，在 M2 选型                      | 禁用原始 HTML，严格处理链接，模型文本不执行                |
| 词句数据  | 本地保存，JSON/CSV 导出                             | 数据可迁移；不绑定远程账号                                 |
| 测试      | Rust 单元/协议测试、Vitest、关键流程 E2E 按阶段引入 | 不为空骨架添加镜像测试，优先覆盖会造成数据或会话错误的逻辑 |
| 许可/名称 | MIT / Parley                                        | 工作名称与应用标识在首个公开发布前复核；不声明名称独占性   |

M0 仅安装当前骨架实际使用的依赖；不提前引入数据库、Markdown、网络或测试大套件。

## 3. 里程碑及验收标准

预计工作量按单人集中开发计，为粗估，不含平台账号、签名证书、外部协议变更等等待时间。每阶段以验收结果决定是否进入下一阶段。

### M0 — 基本工作区与计划（本次，约 0.5–1 天）

交付：

- Git `main` 分支、本地初始提交、忽略规则和 MIT 许可。
- Vue/TypeScript/Vite/Pinia 前端和 Tauri/Rust workspace。
- 双对话区域与生词本空状态，明确显示功能未接入。
- 最小 Rust 命令 `get_runtime_info` 验证前后端通信。
- 工具版本、锁文件、格式化、构建、环境诊断及三平台 CI 配置。
- README、详细开发计划、架构和开发操作文档。

验收：前端构建成功；Rust 格式和 Clippy 通过；Linux 桌面程序可构建；界面和 IPC 完成实际检查，记录无法验证的其他平台；Git 首次提交可追溯。

### M1 — Codex 连接、认证与能力验证（约 2–3 天，依赖 M0）

任务：

1. 探测用户安装的 Codex 可执行文件和版本，提供手动选择路径；首版不静默下载或升级。
2. Rust 托管 `codex app-server` 子进程，以 stdio 交换消息，stderr 单独收集并脱敏。
3. 完成 `initialize` / `initialized` 握手；为每个请求分配 ID、超时和响应路由。
4. 接入账号查询、官方浏览器/设备码登录、取消和登出；令牌由 Codex 管理，不向 Vue 暴露。
5. 接入 `model/list` 分页和额度状态；显示可用模型，不承诺每个账号都能选择 Luna。
6. 实测同一进程内两个 thread 的并发、事件路由、模型覆盖和取消能力。
7. 验证能否在指定版本上施加适合纯聊天的工具限制、独立指令及工作目录隔离。不能仅靠 prompt 限制进程权限。
8. 从已选 Codex 版本生成/校验协议类型与脱敏 fixture，记录支持版本；不依赖未确认的字段。

连接状态：`stopped → starting → ready`；认证、额度和活动 turn 分开建模；进程错误进入可恢复状态。重启后不得自动重发已提交的用户 turn。

验收：缺少 CLI、未登录、登录取消、过期、无模型、额度不足、超时、异常退出都有可理解的状态；断开连接可重连；日志无凭据；关闭应用后无遗留子进程。

阶段决策：若双会话或工具限制不能满足首版要求，先更新设计和兼容说明。个人订阅可用于具体集成的判断依据需与当前官方政策保持一致；技术可用不等于项目已获单独批准。

### M2 — 双会话与目标语言对话（约 3–4 天，依赖 M1）

主对话：

- 创建/恢复会话、流式消息、停止生成、失败后显式重试。
- 系统指令约定目标语言、学习水平和交流风格，prompt 带版本号。
- 输入法合成期间不触发 Enter 发送；支持 Ctrl/Cmd+Enter、草稿保留。
- 将“必须使用目标语言”落实为应用行为：检测非目标语言的明确输入并引导使用辅导区；人名、代码、引用、数字和短句允许合理例外。
- 为语言检测设计策略接口。先评估跨语言候选方案，再决定本地识别与置信度阈值；不能以“只包含拉丁字母”区分英语、法语等语言。
- 低置信度显示提醒；严格模式与允许例外的规则在 UI 中明确说明。模型输出语言偏离时提供重新生成，不声称 prompt 能绝对保证语言。

辅导区：

- 独立 thread 和 prompt，允许母语；候选轻量模型由可用列表选择。
- 四种入口：自由提问、母语转目标语言、选句翻译、词义/语法解释。
- 仅在用户触发时调用；传入选中内容、原句、必要上下文及语言设置。
- 结果可手动插入主输入框，不自动发送；主会话不混入辅导记录。
- 两区各有生成/取消状态；可同时工作；取消某一区不会影响另一区。

验收：完成真实多轮语言学习流程；交错流事件不串窗；取消、断线、恢复不重复消息；Markdown 与恶意文本不能调用桌面命令；长文本、中日韩输入法、阿拉伯语方向正常。

### M3 — 持久化、生词本和注释（约 3–4 天，依赖 M2）

工作区持久化与词句学习已实现。词句功能的范围与验收以 [词句学习开发计划](VOCABULARY_PLAN.md) 为准；此处的早期工期不包含该详细拆分。

任务：

- SQLite 初始迁移，保存语言配置、会话映射、消息、辅导问题和词句。
- 划词/选句菜单：解释、翻译、收藏；支持短语，不以空格切词假设所有语言。
- 收藏保存原始拼写、目标语言、上下文、释义、注释和来源定位。
- 同词不同语境可保存为多个释义/出现记录；相同收藏操作保持幂等。
- 生词列表搜索、语言筛选、编辑、删除与撤销。
- JSON 完整导出/导入和 CSV 简单导出；导入校验格式版本与大小。
- 删除会话时可保留收藏中的原句快照；退出或崩溃后恢复已确认数据。
- 设置界面支持任意目标语言的 BCP 47 标识/名称，预设列表仅作便利选择。

验收：离线可查看/编辑词句；重启保留数据；迁移失败不破坏旧库；中文、重音、RTL 文本往返导入导出不丢失；损坏/重复导入有明确处理。

### M4 — 学习体验完善（约 2–3 天，依赖 M3）

- 主对话的可选纠错模式：不打断、发后简评、手动检查。
- 水平和回答长度设置；辅导答案先给可用表达，再解释差异。
- 收藏增加标签、掌握程度和轻量复习队列；复杂间隔重复算法单独决策。
- 键盘选句、快捷键、字体大小、主题、RTL 和更窄窗口适配。
- 评估把辅导区弹出为独立 Tauri 窗口：状态由 Rust/统一 store 协調，保持同一个 tutor thread，窗口关闭不丢记录。
- 显示账号返回的额度信息，避免把模型费用或剩余量伪造成精确数字。

验收：首次用户能独立完成“聊天 → 求助 → 收藏 → 再次查看”；全部关键操作可用键盘完成；自动辅导不会产生未预期的连续调用。

### M5 — 发布前验证与开源交付（约 2–3 天，依赖 M4）

- 完成 Linux、Windows、macOS 真机启动和官方登录验证；CI 编译成功不能替代 WebView/登录真机检查。
- 测试安装、升级、保留数据、卸载说明和崩溃恢复。
- 固定经过验证的最低 Codex 版本、协议兼容范围和安装指引。
- 整理数据存放位置、凭据管理、日志内容、隐私说明、项目许可与第三方依赖许可。
- 确定最终应用 identifier、名称、图标、发布平台和是否签名；公开发布需另行执行。
- 发布说明、贡献指南、问题模板和已知限制。

验收：关键流程 E2E 与数据恢复测试通过；有可复现构建流程和完整的已知限制说明；公开产物明确版本和平台。

## 4. 建议实施顺序

关键路径：`M0 → M1 → M2 → M3 → M4 → M5`。

M1 的第一项技术验证应聚焦：官方登录 + 两个独立 thread + 轻量模型选择 + 流式路由 + 工具限制。这个结果决定后续 UI 和数据库接口。不要先把所有词典功能做完，再验证模型连接。

每阶段提交建议保持小且可运行，例如：

1. `feat(codex): manage app-server lifecycle`
2. `feat(auth): add local ChatGPT sign-in`
3. `feat(chat): stream isolated conversation and tutor threads`
4. `feat(vocabulary): persist entries with source sentences`

## 5. 测试策略与质量门槛

| 范围     | 优先验证                                                              |
| -------- | --------------------------------------------------------------------- |
| 协议层   | 乱序响应、未知事件、分段 UTF-8、单行大小限制、超时、取消、进程退出    |
| 会话层   | 主/辅 thread 隔离、turn ID 关联、取消晚到事件、重复通知、重连不重发   |
| 提示词   | 同一意图的母语/目标语言回答、水平适配、引用文本中的指令不改变助手角色 |
| 语言识别 | 相近语言、短句、中英混合、代码、人名、RTL、IME                        |
| 存储层   | 外键、迁移回滚、重复收藏、来源删除、事务和导入导出往返                |
| UI       | 键盘、输入法、长消息、离线状态、模型不可用、额度不足、流式自动滚动    |

M0 运行静态检查和实际启动验证；从 M1 开始为以上行为添加有意义的自动测试。CI 不使用真实账号，也不消耗模型额度；真实登录和模型验证在本机显式执行。

## 6. 首版完成定义

- 用户能够使用自己的 Codex 登录完成双会话语言学习。
- 目标语言对话与母语辅助互不干扰；模型与额度状态真实可见。
- 划词、注释、查询和数据导出构成完整本地学习闭环。
- 用户凭据留在官方 Codex 认证体系；前端仅获得所需状态。
- 不依赖自动操作 ChatGPT 网页，不承诺同步网页版记忆或历史。
- 三个平台的验证结论、支持版本、数据位置和已知限制都有文档。
