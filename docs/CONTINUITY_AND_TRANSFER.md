# 续聊、伴随窗口重连与词句迁移

本文描述 `0.4.0-alpha.3` 的源码与本地安装包；GitHub 上已发布的 `0.4.0-alpha.2` 尚不包含这些功能。

## 重填密钥后续聊

在原服务配置中重新填写同一个 API Key，即可继续原对话。“仅本次会话”重启后仍需填写密钥，但不再因此要求新建对话。切换到其他密钥会保持隔离；换回原密钥后可以恢复对应对话。

系统凭据库与临时保存使用同一套绑定规则。改为“仅本次会话”时会删除原系统凭据，防止重启后意外恢复另一把旧密钥；凭据库拒绝删除时保留原状态并提示重试。系统凭据写入失败也不会覆盖当前可用密钥。

数据库保存每个服务独立的随机盐、单向指纹和不透明绑定 ID。指纹包含服务 ID、地址和密钥，用于辨认是否为原凭据；原始密钥仍只在内存或系统凭据库，不进入 SQLite 或备份。

升级前已保存的系统凭据，在能读取并核对原密钥时沿用旧绑定。升级前已经丢失的临时密钥没有可供核对的指纹，不能猜测它属于哪个账号；这类旧对话可用现有“带入历史并使用当前模型”继续可见内容。此后新保存的密钥支持重启辨认。

## 重开语法窗口

原生 Codex / Claude Code 仍按原来的命令启动。语法窗口关闭后，在同一目录的另一个终端运行：

```bash
parley-cli --reconnect
```

它只打开语法窗口，不启动第二个模型 CLI，也不改变原终端的 PID、输入或会话。默认选择当前目录最近一次仍在运行的伴随记录；没有运行中的记录时提示指定历史会话，不自动打开过期缓存。需要指定时：

```bash
parley-cli --list-companions
parley-cli --reconnect --session <ID>
```

源码开发时使用 `target/debug/parley-cli`，或用 `--gui-bin` 指定配套 GUI。已有工作区窗口打开时会提示先关闭，避免两个 GUI 同时写同一个数据库。

Claude 的同步回调由独立的短时本地进程处理，不再依赖 GUI 内的 HTTP 接收器。关闭 GUI 期间继续保存最近十二条可见消息，重开后读回。Codex 继续使用官方历史接口。CLI 恢复前、或启动伴随模式之前未收到的 Claude 历史仍不读取。

记录保存在系统缓存目录的 `org.parley.desktop/companions/<ID>`。Unix 会话目录权限为 0700；只保留有限可见上下文，不保存原始 hook 载荷。GUI 的“伴随会话”可选择、取消关联和清理历史缓存；命令行用 `--clean-companions` 清理已结束的记录。运行中的记录禁止清理；旧版记录显示状态未知，批量清理会跳过。详见[终端伴随说明](TERMINAL_COMPANION.md)。

## 在 Web 与桌面之间迁移词句

1. 桌面：打开词句页的“导入与导出”，选择“导出 JSON”。需要迁移回收站时勾选“导出时包含回收站”。
2. Web：在词句页展开“词句迁移 · Web ↔ 桌面”，选择“导入词句 JSON…”。
3. 检查预览后确认。新增记录合并到现有清单，重复记录跳过；同一记录内容不同则默认保留本地，可选择作为另一条导入。
4. 从 Web 回到桌面：选择“导出词句 JSON”，然后在桌面的“导入 JSON…”中选择文件。

| 内容                               | 迁移后的行为                                         |
| ---------------------------------- | ---------------------------------------------------- |
| 词句、类型、语言、释义、注释、标签 | 完整保留；Web 可以编辑主要文本字段                   |
| 多个原句与来源后端                 | 完整保留；Web 默认展示第一条，编辑窗口可展开其他来源 |
| 识义卡片                           | 可在两端继续复习，保留原排程版本和到期时间           |
| 表达卡片与评分／撤销历史           | 两端均可复习，保留评分与撤销历史                     |
| 回收站                             | 保留删除状态；Web 可查看并恢复                       |
| 聊天、草稿、API 配置和密钥         | 不属于词句文件；迁移不替换当前工作区或清除密钥       |

格式为 `parley-vocabulary` JSON v3，两端同时接受桌面 v1/v2。v3 扩大文本与标签范围，并支持 Web 的 60 天复习阶段；旧客户端会拒绝新版文件，需要更新源码或安装支持该版本的后续包。

旧桌面卡片保留 scheduleVersion 1，记住后的间隔为 1/3/7/14/30 天，最后一级仍为 30 天。Web 原生卡片使用版本 2，增加 60 天阶段。跨端复习不重置阶段或改写过去的评分记录。

Web 旧词句没有选区坐标，迁移时将完整原文作为导入材料保留，不猜测最初选中的位置。旧自由文本语言名称保存在语言名称字段，无法解析成语言代码时使用 `und`；回到 Web 后仍显示原名称。

词句文件限 512 MiB、50,000 条词句、50,000 条来源和 100,000 条复习记录。每条词句最多 100 个来源、30 个标签、两个方向的复习卡；词句与释义各 10,000 字符、注释 16,000 字符、单个标签 100 字符、来源原文 2,000,000 字符。导出与导入共用边界，超过限制明确报错，不静默截断。

Web 完整工作区备份仍使用原来的 JSONL 入口。新写入 format 3，将多来源和复习历史分别成行，防止大词条超过单行限制；继续读取旧 JSON 和 JSONL format 2。词句 JSON 与完整工作区备份用途不同；界面会提示从对应入口导入。Web 词句的完整迁移记录也会随工作区备份保留。

## 验证

- Rust：实际关闭并重开数据库，重填原密钥后沿用会话及协议续聊状态；其他密钥拒绝续聊。模拟凭据库覆盖旧绑定升级、保存方式切换、写入和删除失败。
- 进程：Linux 原生 Tauri/WebKit 窗口在隔离 X11 环境完成关闭、重开，确认新 GUI PID、原生终端 PID 不变，窗口读回 Claude 会话；另有启动器集成测试关闭 GUI 后继续投递事件，再重开 GUI，核对原生进程 PID 不变、没有启动第二个原生 CLI。
- Claude Code：本机 `2.1.269` 配合本地 API 服务验证 command hooks，并确认用户原有 Stop hook 仍执行。未调用真实厂商 API。
- 数据：Rust 和 Web 共用包含多来源、双向卡片、两种排程和回收站的样本；另由真实 Web 序列化代码生成大字段文件，交给 Rust 导入并逐字段比较导出结果。
- 浏览器：Playwright 检查迁移、编辑、导出、刷新、重复导入和故障回滚，确认当前密钥及草稿保留。原有保存、任务切换、输入法和分页回归继续运行。
- 升级：从 schema 8 升到 9 后对比旧卡片和历史，核对 SQLite 外键；旧备份幂等、冲突副本和升级前备份测试保留。

可复现的跨语言检查：

```bash
PARLEY_TEST_LEARNING_EXPORT=/tmp/parley-learning.json npm test
PARLEY_TEST_LEARNING_EXPORT=/tmp/parley-learning.json cargo test --lib runtime_web_export_imports_and_roundtrips_without_truncation -- --ignored
```

原生 Windows/macOS 窗口、系统凭据库及真实厂商 API 未在这次修改中实测。历史验证范围仍见[兼容记录](BACKEND_COMPATIBILITY.md)。

## Web 表达复习

补充释义后，可以分别加入识义和表达复习。识义展示词句、回忆含义；表达展示含义，点击“显示答案”后才展示目标词句和原句。回忆输入可选，同义表达由自己判断。

复习方向可以筛选。忘记安排到十分钟后，吃力安排到一天后，记住沿用卡片的排程版本。暂停再恢复不会重置进度；回收站和暂停卡片不进入队列。删除释义的词句会暂停出题，补充后继续。

评分先写入 IndexedDB，成功后进入下一题；写入失败保留题目、输入和原排程，可直接重试。撤销只作用于最近一次评分，并拒绝覆盖此后已经改变的卡片。Web 新建的词句在加入复习时使用与桌面相同的双向卡片和历史结构。

安装包升级的实际检查见[升级验证](UPGRADE_VALIDATION.md)。
